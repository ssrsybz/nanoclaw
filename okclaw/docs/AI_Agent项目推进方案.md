# 复盘大师 AI Agent 项目推进方案

## 1. Agent 的核心定位

在 AI Agent 独立工作模式下，复盘大师不应该被理解成一个普通的股票行情网站，也不应该被做成一个简单的股票问答机器人。

更合适的定位是：

> 一个长期跟随用户的 A 股复盘主理人。它每天自动整理市场，用 Python 工具验证数据，把用户成功过的判断拆成可复用策略，并在未来市场中持续寻找相似结构。

这个 Agent 的目标不是直接告诉用户买什么，而是帮助用户：

1. 更快理解当前 A 股市场结构；
2. 记录和理解自己的成功经验；
3. 用数据佐证自己的市场判断；
4. 把主观交易经验拆解成可编码的策略条件；
5. 在未来市场中持续寻找类似机会；
6. 逐步形成个人化、可验证、可复用的复盘体系。

因此，复盘大师的 Agent 不应是“荐股 Agent”，而应是：

> 用户个人交易认知的复盘 Agent。

---

## 2. Agent 应该长期理解用户

复盘大师的核心前提是：用户不是小白，用户本身有自己的股票理解、交易语言和复盘习惯。

所以 Agent 最重要的能力不是一次性回答，而是长期学习用户。

### 2.1 理解用户关注的数据

Agent 应该逐渐记住用户经常关注哪些市场数据，例如：

- 涨停数量；
- 跌停数量；
- 连板高度；
- 首板数量；
- 二板晋级率；
- 炸板率；
- 封板率；
- 板块强度；
- 题材扩散；
- 龙头股表现；
- 昨日涨停溢价；
- 成交额核心票；
- 情绪冰点 / 高潮；
- 高位股负反馈；
- 低位补涨；
- 指数和题材是否共振。

这些不是简单指标列表，而是用户理解市场的入口。

Agent 要逐渐知道：

> 这个用户看市场时，最在意的结构是什么。

### 2.2 记录用户成功过的判断

项目口号是：

> 只要你成功过 1 次，我们就能持续让你成功。

这句话应该被理解为产品方法论，而不是单纯宣传语。

每当用户认为某次交易、判断、观察是成功的，Agent 应该记录并拆解这次成功：

- 成功发生在什么日期？
- 标的是什么？
- 当时指数环境如何？
- 当时市场情绪如何？
- 当时主线题材是什么？
- 个股处于什么位置？
- 涨停时间早不早？
- 封单强不强？
- 板块有没有小弟助攻？
- 成交额有没有放大？
- 换手是否健康？
- 前一天或前几天有没有异动？
- 用户当时为什么会关注它？
- 用户真正做对的是哪一步？

Agent 要做的不是简单记录“这次赚钱了”，而是把成功案例拆解成未来可以复用的数据结构。

### 2.3 理解用户自己的策略语言

用户可能会使用很多带有主观交易经验的词，例如：

- 有辨识度；
- 情绪载体；
- 卡位；
- 补涨；
- 题材没发酵完；
- 冰点转暖；
- 像某年某月那一波；
- 封板质量不错；
- 板块有梯队；
- 龙头气质；
- 弱转强；
- 分歧转一致。

这些词不一定是标准金融指标，但它们是用户的交易语言。

Agent 的核心价值之一，就是把这些语言翻译成可验证的数据条件。

例如，“有辨识度”可以拆成：

- 成交额排名靠前；
- 板块内涨幅靠前；
- 涨停时间早；
- 连板高度较高；
- 被多个资讯源提及；
- 同板块跟涨个股数量多；
- 当日换手充分；
- 次日溢价较高；
- 近期反复活跃。

这就是 Agent 的关键作用：

> 把用户主观经验翻译成客观数据结构。

---

## 3. 推荐架构：一个主 Agent + 多个工具能力

早期不建议一上来拆很多复杂 Agent。更稳的方式是：

> 先做一个强主 Agent，再给它配工具。

可以先把它设计成：

```text
复盘主理人 Agent
    ├── 数据采集工具
    ├── 市场概览工具
    ├── 涨停/连板分析工具
    ├── 板块题材分析工具
    ├── 个股画像工具
    ├── 策略匹配工具
    ├── 成功案例记忆工具
    ├── 回测/验证工具
    └── 复盘报告生成工具
```

这个结构的好处是：

1. Agent 负责理解用户意图；
2. Python 工具负责真实数据计算；
3. 数据库 / 文件系统负责沉淀长期记忆；
4. 后续可以平滑拆分成多 Agent 架构。

## 4. Agent 应该配置的核心工具

因为项目语言选用 Python，所以工具本质上可以是 Python 函数、脚本或服务接口。

### 4.1 市场总览工具

用于回答：

> 今天 A 股整体是什么状态？

工具应输出：

- 上证指数、深成指、创业板、科创板涨跌；
- 两市成交额；
- 上涨家数 / 下跌家数；
- 涨停数量；
- 跌停数量；
- 炸板率；
- 连板高度；
- 赚钱效应；
- 亏钱效应；
- 市场情绪阶段。

示例工具：

```text
get_market_overview(date)
```

### 4.2 涨停与连板分析工具

A 股短线复盘中，涨停和连板结构非常重要。

工具应输出：

- 今日涨停列表；
- 首板、二板、三板、四板以上；
- 最高板；
- 涨停时间；
- 封单金额；
- 炸板次数；
- 所属概念；
- 是否一字板；
- 是否放量；
- 是否换手板；
- 昨日涨停今日表现。

示例工具：

```text
get_limit_up_pool(date)
analyze_limit_up_structure(date)
```

### 4.3 板块 / 题材强度工具

用于回答：

> 今天主线在哪里？

工具应输出：

- 板块涨幅排行；
- 板块成交额排行；
- 板块内涨停数量；
- 板块内核心个股；
- 板块是否扩散；
- 板块是否持续；
- 板块是否第一次爆发；
- 板块是否高潮。

示例工具：

```text
get_sector_strength(date)
analyze_theme_diffusion(date, theme)
```

### 4.4 个股画像工具

用于回答：

> 这个票为什么值得关注？

工具应输出：

- K 线结构；
- 涨跌幅；
- 成交额；
- 换手率；
- 量比；
- 流通市值；
- 所属概念；
- 近期异动；
- 是否涨停；
- 是否放量突破；
- 是否板块核心；
- 是否历史活跃股；
- 龙虎榜 / 资金信息。

示例工具：

```text
get_stock_profile(symbol, date)
analyze_stock_behavior(symbol, date)
```

### 4.5 成功案例记录工具

这是复盘大师最核心的工具之一。

当用户说：

> 这个案例记下来，这是我做对的一次。

Agent 应该调用工具保存：

- 日期；
- 标的；
- 用户当时的判断；
- 当时市场环境；
- 当时数据快照；
- 用户成功原因；
- 可复用条件；
- 后续验证结果。

示例工具：

```text
save_success_case(case)
```

这里保存的不是简单笔记，而是未来策略匹配的种子。

### 4.6 策略条件抽象工具

用于把成功案例变成规则。

例如用户说：

> 我当时看它，是因为它在板块启动第一天就涨停，而且成交额明显放大，第二天低开不破，第三天反包。

Agent 应该抽象成：

```text
条件 1：所属板块当日涨幅进入前 N
条件 2：个股当日涨停
条件 3：成交额较过去 20 日均值放大 X 倍
条件 4：次日没有大幅低开
条件 5：第三日重新走强
```

示例工具：

```text
extract_strategy_conditions(success_case)
```

### 4.7 策略匹配工具

用于每天检查：

> 今天有没有类似用户过去成功模式的票？

工具应输出：

- 命中的历史模式；
- 今日相似个股；
- 相似度；
- 命中条件；
- 未满足条件；
- 需要用户重点观察的点。

示例工具：

```text
match_user_patterns(date)
```

这就是项目口号真正落地的地方：

> 你成功过一次，系统以后就帮你找类似结构。

### 4.8 回测 / 验证工具

不能只凭感觉说“这个策略有效”。

Agent 应该可以让 Python 去验证：

- 过去一年出现过多少次；
- 次日平均收益；
- 三日平均收益；
- 最大回撤；
- 成功率；
- 失败样本；
- 最容易失效的市场环境；
- 牛市、震荡、退潮期表现差异。

示例工具：

```text
backtest_pattern(pattern_id, start_date, end_date)
```

### 4.9 复盘报告生成工具

每天输出一份用户能快速看的复盘。

报告可以包括：

```text
1. 今日市场状态
2. 情绪周期判断
3. 主线题材
4. 涨停结构
5. 连板梯队
6. 核心个股
7. 高位风险
8. 用户历史成功模式匹配
9. 明日重点观察
10. 需要继续验证的假设
```

示例工具：

```text
generate_daily_review(date, user_id)
```

## 5. Agent 的日常工作方式

建议设计成：

> 固定日常流程 + 用户随时追问。

### 5.1 每日收盘后自动运行

每天收盘后，Agent 可以自动执行：

```text
1. 拉取当日行情数据
2. 拉取涨停 / 跌停数据
3. 拉取板块 / 题材数据
4. 计算市场情绪指标
5. 识别主线方向
6. 匹配用户历史成功模式
7. 生成一份初步复盘报告
8. 标记需要用户确认的问题
```

Agent 输出不应该是简单行情日报，而应该类似：

```text
今天市场更像是“题材轮动 + 高位分歧”状态。
与用户过去成功案例「低位题材启动第一天」相似的方向有 2 个：机器人、AI 应用。
但当前不同点是成交额不足，且高位股负反馈较重，所以需要降低确定性评级。
```

这种输出才像一个懂用户的复盘助手。

### 5.2 用户随时追问

用户可能会问：

> 今天机器人这个方向你怎么看？

Agent 不应该泛泛回答，而应该：

1. 调用板块强度工具；
2. 调用板块内个股工具；
3. 调用涨停结构工具；
4. 检索用户过去是否做过类似题材；
5. 给出数据支持；
6. 明确哪些是事实，哪些是假设。

输出结构可以是：

```text
事实：
- 机器人板块今日涨幅第 3
- 板块内 9 只涨停
- 其中 3 只是首板，2 只是二板
- 核心票成交额放大明显

和用户历史成功模式的相似点：
- 都是板块启动初期
- 都出现了低位批量首板
- 都有一个成交额核心票带动

不同点：
- 今天指数没有明显共振
- 高位股仍有负反馈
- 板块内尚未形成清晰高度龙

结论：
- 可以列为明日重点观察方向
- 但目前更像“试探性启动”，还不能确认主线
```

## 6. Agent 需要的四类长期记忆

复盘大师一定要有长期记忆，否则无法体现“持续让你成功”。

### 6.1 用户偏好记忆

记录：

- 用户偏短线还是趋势；
- 用户关注涨停还是趋势股；
- 用户偏题材还是业绩；
- 用户喜欢看哪些指标；
- 用户不喜欢哪些分析方式；
- 用户常用的市场术语。

### 6.2 成功案例记忆

记录用户认可的成功样本。

推荐格式：

```text
案例名称：
日期：
标的：
当时市场环境：
用户判断：
关键数据：
成功原因：
可复用条件：
后续表现：
```

### 6.3 策略规则记忆

从成功案例中抽象出来的规则。

推荐格式：

```text
策略名称：
适用市场环境：
入选条件：
排除条件：
验证指标：
历史成功样本：
历史失败样本：
当前可信度：
```

### 6.4 数据源质量记忆

记录不同数据源的可靠性。

例如：

- 哪个源涨停数据更准；
- 哪个源板块概念更全；
- 哪个源延迟严重；
- 哪个源适合历史回测；
- 哪个源适合实时监控。

这对项目长期发展非常关键。

## 7. Agent 的边界

这个项目必须明确边界。

Agent 不应该直接输出：

```text
买这个。
明天一定涨。
这个票必成龙头。
满仓干。
```

这会让产品变成不可靠的荐股工具。

Agent 更应该输出：

```text
当前它命中了用户过去成功模式中的 4 个条件，但还缺少“板块持续性确认”。
如果明天板块继续扩散，且核心票不出现明显负反馈，则这个模式的相似度会进一步提高。
当前更适合列为观察对象，而不是结论对象。
```

也就是说，Agent 的输出结构应该是：

```text
事实 + 数据 + 相似模式 + 风险条件 + 观察点
```

而不是：

```text
买卖指令
```

## 8. 后续多 Agent 演进方向

等主 Agent 跑顺后，可以逐步拆成多个专业 Agent。

### 8.1 数据源 Agent

负责：

- 寻找新数据源；
- 验证数据准确性；
- 比较不同数据源；
- 维护数据接口；
- 标注数据延迟和缺失。

### 8.2 市场复盘 Agent

负责：

- 每日市场总结；
- 情绪周期判断；
- 涨停结构分析；
- 板块强弱分析。

### 8.3 策略研究 Agent

负责：

- 拆解用户成功案例；
- 抽象策略条件；
- 生成候选规则；
- 和历史数据对比。

### 8.4 回测验证 Agent

负责：

- 把策略条件转成 Python 回测；
- 统计胜率、收益、回撤；
- 找失败样本；
- 判断策略适用环境。

### 8.5 报告 / 界面 Agent

负责：

- 生成日报；
- 生成周报；
- 生成策略卡片；
- 设计可视化看板。

涉及网页设计和生成时，需要遵守项目规则，调用前端设计相关技能。

---

## 9. 总结

复盘大师在 AI Agent 模式下，最重要的不是做一个“能聊天的股票工具”，而是做一个长期跟随用户的复盘主理人。

它应该具备四个核心能力：

```text
看市场
懂用户
记成功
找相似
```

这四个能力如果跑通，复盘大师的产品灵魂就会非常清晰：

> 用户成功过一次，系统就帮助用户把这次成功拆解、验证、编码，并在未来市场中持续寻找相似结构。
